# Ідея винаходу та критерії контролю результатів симуляції

**Контекст:** дисертаційна робота, новизна НН-3/НН-4 (див. `NOVELTY_MASTER.md`); підстава для документа — результати патентно-аналітичного звіту (`patent_search_report.md`, `patent_search_extended_analize`) та технічного завдання на MIL-комплекс (`technical_spec_dev.md`, `static_model_spec.md`).

## 1. Головна ідея винаходу

### 1.1. Формулювання

**Спосіб адаптивного прогнозного керування з функціонально розподіленою ядерною моделлю,** у якому невизначеність, оцінена GP-модулем у спільному з KRR-моделлю просторі RKHS, керує трирежимним перемиканням матриці штрафних ваг `R(k)` у функціоналі MPC, а SVR виконує попередню фільтрацію аномальних спостережень.

Магнітна сепарація залізорудної сировини розглядається лише як приклад промислової придатності, а не як обмеження об'єкта винаходу.

### 1.2. Причинно-наслідковий ланцюг (патентне ядро)

```
аномалія / новий режим
      ↓
SVR-фільтрація + зростання σ²_GP(ξ(k))
      ↓
перемикання R(k) між штатним / обережним / консервативним режимом
      ↓
обмеження небезпечних керуючих дій
```

Саме цей ланцюг становить технічну сутність винаходу і виноситься в центр незалежного пункту формули.

### 1.3. Послідовність ознак для незалежного пункту формули

На кожному кроці керування `k`:

1. отримують поточні технологічні дані;
2. формують регресорний вектор `ξ(k)`;
3. SVR-модулем визначають, чи є спостереження аномальним;
4. неаномальні дані включають у ковзне навчальне вікно;
5. KRR з RBF-ядром формує прогнозну модель об'єкта керування;
6. GP-модуль на узгодженій ядерній матриці оцінює `σ²_GP(ξ)`;
7. залежно від `σ²_GP` система вибирає один із трьох режимів `R(k)`:
   - штатний: `R(k) = R₀`;
   - обережний: `R(k) = R₀ + α·σ²_GP(ξ)·I` (або діагональна модифікація);
   - консервативний: `R(k) = γ·R₀`, `γ > 1` (або з обмеженим upper-bound);
8. MPC розв'язує оптимізаційну задачу з оновленою `R(k)`;
9. керуючий вплив подається на фізичний виконавчий механізм.

### 1.4. Обґрунтування патентоспроможності

| Критерій | Підстава |
|---|---|
| Новизна | Серед 10 проаналізованих патентів-аналогів жоден не розкриває комбінацію всіх чотирьох ознак (SVR-фільтр + KRR-модель + GP-дисперсія + трирежимна `R(k)`); максимальний строгий збіг — 2/4 (WO 2025/043459 A1, CN 120085540 A) |
| Винахідницький рівень — ефект 1 | Спільна матриця Грама `(K+λI)⁻¹` для KRR і GP знімає окрему `O(n³)` інверсію для GP, що уможливлює GP-наглядач у реальному часі на PLC/DCS |
| Винахідницький рівень — ефект 2 | SVR з ε-нечутливою трубкою знижує ймовірність потрапляння негауссівських викидів у навчальне вікно, що стабілізує оцінювання GP posterior variance і запобігає хибним переходам MPC у консервативний режим |
| Промислова придатність | Реалізованість на PLC, Edge Computing, DCS з підтримкою Python/C++ та QP-розв'язувачів (OSQP, CVXGEN); підтверджується MIL-комплексом (`technical_spec_dev.md`) |

### 1.5. Чим винахід НЕ є (для уникнення слабкої формули)

- не «комбінацією SVR + KRR + GP + MPC» (кожен компонент відомий окремо);
- не «адаптивним MPC з GP» загалом (близько до CN 120085540 A);
- не «GP-MPC з uncertainty propagation» (близько до EP 4363936 / Mitsubishi);
- не «модифікацією process constraints за GP-дисперсією» (близько до US 2023/0279332 A1).

Відмінність — саме у **функціонально-рольовому розподілі** (SVR = фільтр, KRR = номінальна модель, GP = наглядач) у спільному RKHS + **трирежимній адаптації `R(k)` від `σ²_GP(ξ)`**.

## 2. Критерії контролю результатів симуляції

Симуляція повинна підтвердити чотири групи фактів, що прямо обґрунтовують пункти формули винаходу та винахідницький рівень. Перелік сценаріїв і метрик — згідно з `technical_spec_dev.md`, розд. 4.

### 2.1. Працездатність кожного компонента окремо (модульні тести)

| Компонент | Що підтверджується | Сценарій / тест |
|---|---|---|
| SVR-фільтр | Імпульсні викиди не потрапляють у навчальне вікно; `N_filtered > 0` | EXP-2; модульні тести на синтетичних аномаліях |
| KRR-модель | Прогноз відтворює відомі функції з заданою точністю | Модульні тести |
| GP-наглядач | `σ²_GP` узгоджується з аналітичними значеннями на простих випадках | Модульні тести |
| QP-розв'язувач | Правильний розв'язок на задачах з відомим результатом | Модульні тести |

### 2.2. Каузальний ланцюг `σ²_GP → R(k) → керування` (центральна теза патенту)

| Що підтверджується | Сценарій | Свідчення |
|---|---|---|
| OOD-вихід спричиняє зростання `σ²_GP` | EXP-3 | Графік `σ²_GP(t)` |
| Зростання `σ²_GP` спричиняє перехід у консервативний режим | EXP-3 | `p_консерв > 0`; синхронні траєкторії `σ²_GP`, `R(k)`, режиму |
| Повернення в навчальний домен повертає систему в штатний режим | EXP-3 | Зворотний перехід без розгойдування (гістерезис) |
| Імпульсні викиди НЕ викликають хибних переходів у консервативний режим | EXP-2 | `p_консерв` за наявності SVR ≤ `p_консерв` без SVR |

Вихідні документи: `7.3` (графік `σ²_GP` та перемикання режимів), `7.4` (графік `R(k)` як функції `σ²_GP`).

### 2.3. Технічний ефект порівняно з базовими лініями (доказ винахідницького рівня)

**Базові лінії** (`baselines/`, ТЗ розд. 3.3):
- `classic_mpc` — MPC з фіксованою `R₀`;
- `prototype_mpc` — MPC з адаптацією `R` за автокореляцією похибки прогнозу (аналог Honeywell US 8,185,217 B2).

**Абляційний аналіз** (EXP-5) — внесок кожного компонента:

| Конфігурація | Перевіряє |
|---|---|
| KRR-MPC з фіксованою `R₀` | Базова якість без адаптації |
| KRR-MPC + GP-дисперсія, без адаптації `R` | Лише наявність GP не дає виграшу |
| KRR-MPC + adaptive `R(k)`, без SVR | Виграш від адаптації, але вразливість до викидів |
| Повна схема SVR + KRR + GP + adaptive `R(k)` | Цільова конфігурація |

**Критерій підтвердження ефекту:** повна схема перевершує обидві базові лінії хоча б за однією з груп метрик (за фіксованих інших), без істотного погіршення інших:

| Група | Метрики |
|---|---|
| Безпека | `N_viol`, `T_viol` (порушення технологічних обмежень) |
| Плавність керування | `TV(B)`, `TV(ρ)`, `TV(Q)` |
| Якість відстеження | `RMSE_βFe`, `RMSE_ε` |
| Інтегральний показник | `J_integral` |

Очікувані якісні факти, що мають проявитися:
- схема без SVR гірша на EXP-2 (викиди);
- схема з фіксованою `R` гірша на EXP-3 (OOD);
- повна схема не гірша за `classic_mpc` на EXP-1 (штатний режим — відсутність «штрафу» за наявність адаптації).

### 2.4. Обчислювальна спроможність у реальному часі (EXP-6)

| Що підтверджується | Свідчення |
|---|---|
| Спільна матриця Грама `(K+λI)⁻¹` дає той самий результат, що дві окремі інверсії | Чисельна різниця в межах похибки округлення |
| Виграш продуктивності за рахунок спільної інверсії | `t_step` (спільна) ≤ `t_step` (окремі) |
| Сумісність з циклом промислового контролера | `t_step` менший за період дискретизації об'єкта |

Це прямий доказ ефекту, заявленого як винахідницький рівень (розв'язання проблеми `O(n³)` для GP у реальному часі).

### 2.5. Методологічна валідність (передумова прийнятності результатів)

Без виконання цих вимог жодні KPI не вважаються підтвердженими.

| № | Вимога | Джерело |
|---|---|---|
| М1 | Модель об'єкта пройшла протокол валідації (перевірки 8.1–8.10) | `static_model_spec.md` |
| М2 | Дворазовий запуск `run_all.py` дає ідентичні результати | ТЗ розд. 5.7 |
| М3 | Усі ГВЧ ініціалізовані фіксованими seed; перелік задокументований | ТЗ розд. 5.2 |
| М4 | За наявності випадкових компонентів — серія `N ≥ 30` прогонів; результат як середнє ± довірчий інтервал | ТЗ розд. 4.2 |
| М5 | Кожен числовий параметр має в конфігурації коментар-джерело | ТЗ розд. 5.4 |
| М6 | Результати кожного прогону зберігаються з хеш-сумою конфігурації | ТЗ розд. 5.5 |
| М7 | Версія коду фіксується тегом у системі контролю версій | ТЗ розд. 5.8 |

### 2.6. Чого симуляція НЕ підтвердить (обмеження достовірності)

Це обмеження зафіксоване для коректності формулювань у заявці та дисертації:

- **Абсолютну точність `βFe`, `ε`** — еталонних промислових точок `(B, Q, ρ, αFe, βFe, ε)` для ПБМ 90/250 на криворізьких магнетитових рудах у відкритому доступі немає (`static_model_spec.md`, розд. 9.1). Симуляція підтверджує **якісні залежності** та **відносний виграш** проти базових ліній, а не абсолютні значення.
- **Поведінку на реальному об'єкті** — MIL-комплекс є моделлю-в-петлі, не HIL і не польовими випробуваннями.
