# Постмортем — типові помилки розробки

Кожна сесія читає цей файл на початку роботи.

**Статуси:**
- `[active]` — помилка актуальна, уникати
- `[resolved]` — вирішена, залишена як довідка
- `[dismissed]` — виявилася випадковою або нерелевантною, видалити при наступному прибиранні

**Формат запису:**
```
### PM-NNN — Коротка назва
- **Статус:** active | resolved | dismissed
- **Етап:** Е1–Е7 або "загальне"
- **Модуль:** файл або компонент
- **Опис:** що пішло не так
- **Наслідок:** що сталося в результаті
- **Рішення / обхід:** як виправили або уникнути
- **Дата:** YYYY-MM-DD
```

## Вирішені помилки

### PM-001 — Tracking error константа у QP (critical)
- **Статус:** resolved
- **Етап:** Е4
- **Модуль:** `mpc_core/qp_solver.py`, `baselines/classic_mpc.py`, `baselines/prototype_mpc.py`
- **Опис:** Помилка відстеження `e = y_pred - y_ref` обчислювалась як константа поза тілом оптимізаційної задачі. У cvxpy константа в цільовій функції не впливає на змінну рішення `delta_u`, тому солвер завжди повертав `delta_u = 0`.
- **Наслідок:** Контролер не відпрацьовував завдання — керуючий вплив завжди залишався на попередньому значенні.
- **Рішення:** Введено матрицю лінійного gain `G` (n_y × n_u). Передбачення на кроці `i` горизонту: `y_hat(i) = y_pred(i) + G @ Σ_{j=0}^{i} Δu_j`. Тепер `e(i) = y_hat(i) - y_ref` є функцією від `delta_u`.
- **Дата:** 2026-05-15

### PM-002 — Регресор KRR будує identity-маппінг (high)
- **Статус:** resolved
- **Етап:** Е4
- **Модуль:** `mpc_core/mpc_controller.py`
- **Опис:** Регресор будувався як `xi = [y_meas(k), u(k)]` — поточне вимірювання. KRR навчався передбачати `y(k)` з `y(k)` → статичне тотожне відображення, а не предиктивна модель.
- **Наслідок:** KRR не вносив корисної динамічної інформації; прогноз був тотожним поточному виміру.
- **Рішення:** Регресор переведено на затримані дані: `xi(k) = [y(k-1), u(k-1)]`. Зберігається `y_prev` між кроками.
- **Дата:** 2026-05-15

### PM-003 — SVR аномалія: хибна мітка `mean(y_meas)` (high)
- **Статус:** resolved
- **Етап:** Е4
- **Модуль:** `mpc_core/mpc_controller.py`
- **Опис:** Виклик `predict_with_label(xi[:n_y], mean(y_meas))` — `mean(y_meas)` як мітка для SVR, що навчений передбачати `beta_fe` (канал 0). Ця мітка не відповідає жодному каналу, тому класифікація аномалій була хибною.
- **Наслідок:** Некоректна фільтрація спостережень — нормальні дані могли відхилятись, аномальні — прийматись.
- **Рішення:** Перейдено до двох окремих SVR-фільтрів (`svr_beta`, `svr_eps`) по одному на кожен вихідний канал. Виклик: `predict_with_label(xi[:n_y], y_meas[0])` та `predict_with_label(xi[:n_y], y_meas[1])`.
- **Дата:** 2026-05-15

### PM-004 — SVR покриває лише канал βFe (medium)
- **Статус:** resolved
- **Етап:** Е3, Е4
- **Модуль:** `mpc_core/mpc_controller.py`
- **Опис:** SVR навчався лише на `Y_win[:, 0]` (βFe); аномалії виключно в каналі `ε` не виявлялись.
- **Наслідок:** Аномальні вимірювання ε могли потрапляти в навчальну вибірку KRR.
- **Рішення:** Введено два окремих SVR-об'єкти і окреме навчання на кожному каналі (`Y_win[:, 0]` та `Y_win[:, 1]`).
- **Дата:** 2026-05-15

### PM-005 — `SVRFilter.predict()` рахує відстань від нуля (medium)
- **Статус:** resolved
- **Етап:** Е3
- **Модуль:** `kernel_models/svr_filter.py`
- **Опис:** `tube_dist = |y_pred| - ε` — відстань від нуля, а не залишок від моделі. Метод не може визначити outlier без мітки.
- **Наслідок:** `predict()` завжди давав хибну класифікацію (залежала від масштабу, а не від відхилення від SVR-моделі).
- **Рішення:** `predict(x, y_true=None)` — при наявності `y_true` рахує `residual = |y_true - SVR(x)|`; без мітки повертає `tube_dist = 0` (нормально). Рекомендовано завжди передавати `y_true` або використовувати `predict_with_label`.
- **Дата:** 2026-05-15

### PM-006 — `KRRModel.predict_horizon` повертає константу (medium)
- **Статус:** resolved
- **Етап:** Е3
- **Модуль:** `kernel_models/krr_model.py`
- **Опис:** `return np.tile(y_hat, (Np, 1))` — увесь горизонт заповнювався однаковим значенням. MPC не бачив динаміки по горизонту.
- **Наслідок:** QP оптимізував керування без урахування траєкторії системи — неоптимальна стратегія.
- **Рішення:** Рекурентний roll-out: `xi_{k+i+1} = [y_hat_{k+i}, u_prev]`, кожен крок використовує прогноз попереднього. Управління `u_prev` утримується постійним (відкрита петля — QP коригує через gain).
- **Дата:** 2026-05-15
